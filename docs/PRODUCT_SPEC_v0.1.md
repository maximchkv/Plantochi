# Plantochi -- Product Spec v0.1

Проект: Tamagotchi for Plants
Платформа: iOS
Фокус: мягкая геймификация ухода за реальными растениями через обучение, визуал и наблюдение
Язык: RU
Хранение данных: локально (MVP)

⸻

## 1. Продуктовая идея (зафиксировано)

Приложение — это живой обучающий проект, который растёт вместе с пользователем.
Цель — не "не забывать поливать", а:
- научиться замечать признаки состояния растений
- понимать почему нужно делать действия
- видеть последствия и награды заботы
- постепенно вырастить осознанность и уверенность

Игра не наказывает, не давит, не оптимизирует.
Она сопровождает и отражает.

⸻

## 2. Главная петля (ядро системы)

Зафиксировано как основа всей архитектуры.

Каждый элемент опыта — это узел одного из типов:
1. **Индикатор**
   → "на что стоит обратить внимание"
2. **Действие**
   → "что можно сделать и зачем"
3. **Последствие / награда**
   → "что это дало растению / дому / тебе"

Узлы:
- открываются постепенно
- соединяются в дерево знаний
- могут начинаться с любого элемента (не всегда с действия)

⸻

## 3. Основные сущности данных

### 3.1 PlantInstance (Растение)

Одна сущность = одно реальное растение дома.

Хранит:
- id
- имя (пользовательское)
- тип / семейство (ограниченный сет для MVP)
- фото (1+)
- дата добавления
- связанные KnowledgeNode
- расписание действий
- историю действий
- визуальное состояние

Скрытые параметры (не всегда видны):
- условная "влажность"
- накопленный стресс
- накопленный риск
- история ошибок (для обучения)

Видимое состояние:
- визуал (анимация, цвет, форма)
- 1–2 коротких текстовых сигнала (в бета — мотивационные)

⸻

### 3.2 HomeEntity (Дом)

Агрегированная сущность всей системы.

Роль:
- отражает состояние всей экосистемы
- основной источник мета-наград
- визуально растёт и меняется

Состав:
- "комната/дом" (фон, окружение)
- тотем дома (живое создание)
- граф прогресса (абстрактный, не цифры)

Влияние:
- баланс состояния растений
- регулярность заботы
- отсутствие критических рисков

⸻

### 3.3 KnowledgeNode (Узел знания)

Базовая обучающая единица.

Типы:
- Индикатор
- Действие
- Последствие / Награда

Содержит (MVP — все):
- краткое описание
- "что наблюдать"
- "что делать"
- "почему это важно"
- связанные узлы

Открытие:
- через квесты
- через события
- через действия
- через фото/наблюдение

⸻

### 3.4 Quest (Квест)

Обучающая цепочка.

Состав:
- последовательность KnowledgeNode
- может включать:
  - наблюдение
  - действие
  - факт
  - последствие

Параметры:
- срок
- риск
- награда
- состояние (активен / завершён / просрочен)

Ограничение MVP:
Одновременно ≤ 3 активных квеста.

⸻

### 3.5 Achievement / Streak

Ачивки:
- за квесты
- за открытия
- за поведение
- за регулярность

Стрики:
- вход
- действия
- квесты
- наблюдение

❗ Стрики не теряются, фиксируются "пропуски".

⸻

## 4. Экраны MVP

### 4.1 Tab Bar (5 вкладок)
1. Дом
2. Сегодня
3. Квесты
4. Книга
5. Профиль / Ачивки

⸻

### 4.2 Экран «Дом»

Формат:
- изометрическая матрица
- растения — как объекты в пространстве
- постоянная "дыхательная" анимация

Содержит:
- все растения
- сущность дома (комната + тотем)
- граф прогресса системы

Функции:
- визуальное считывание состояния
- вход в растение
- вход в режимы
- кнопка переключения режима

⸻

### 4.3 Экран «Растение»

Режимы:
- **Вид** — визуал + настроение
- **Детали** — индикаторы, история, знания

Действия:
- кнопка "Все действия"
- внутри — список доступных

Подтверждение действия:
- тап → анимация
- предложение:
  - добавить запись в дневник
  - прикрепить фото

⸻

### 4.4 Экран «Сегодня»
- рекомендованные действия
- визуальный риск (цвет + иконка)
- без давления и дедлайнов

⸻

### 4.5 Экран «Квесты»
- активные (≤3)
- завершённые
- будущие (затравки)

⸻

### 4.6 Экран «Книга знаний»

Формат:
- главы + граф связей

Секции:
- Индикаторы
- Действия
- Последствия

Узлы открываются постепенно.

⸻

### 4.7 Экран «Ачивки / Профиль»
- стрики
- достижения
- статистика
- история заботы

⸻

## 5. Действия и риск

### 5.1 Модель действия

Каждое действие имеет:
- тип
- окно выполнения
- уровень риска
- эффект:
  - ранний
  - нормальный
  - поздний
  - пропуск

Отображение риска:
- цвет
- иконка
- визуал
- тон текста

⸻

## 6. Режимы

### 6.1 Наблюдательный
- без задач
- без давления
- только визуал и дневник

### 6.2 Активный день
- больше квестов
- больше сигналов

### 6.3 Отпуск / Пауза
- замораживаются только стрики
- риски продолжают копиться
- пуши минимальны

⸻

## 7. Уведомления

Типы (MVP):
- напоминание о действии
- высокий риск
- атмосферный сигнал (редко)
- факт / открытие
- вечерний отчёт

Интенсивность:
- выбирается на онбординге
- уровни (мягко / нормально / интенсивно)

⸻

## 8. Онбординг
- одна сессия
- атмосферный
- без объяснения систем
- якоря на будущее
- первое растение
- первый индикатор
- первый визуальный отклик

⸻

## 9. Фото и дневник

Дневник:
- автоматические записи
- ручные заметки

Фото:
- при добавлении растения
- по квестам
- по желанию после действий

⸻

## 10. Принципы (важно для разработки)
- нет жёстких наказаний
- нет "проигрыша"
- визуал > цифры
- обучение через опыт
- игра может быть "незаконченной"
- проект рассчитан на долгую жизнь
